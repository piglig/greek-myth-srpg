# engine：规则、模拟、平衡、工坊、美术生成（Go）

所有工具都在一个程序里：`engine/bin/srpg.exe`。战斗规则只有这一份实现，模拟、战棋工坊和可玩原型都用它。

## 构建和测试

```sh
cd engine
go build -o bin/srpg.exe ./cmd/srpg
go test ./...
```

需要 Go 1.25，也可以直接运行 `build.bat`。Godot 原型启动时会找 `bin/srpg.exe`，没有就报错。唯一的第三方依赖是 `gopkg.in/yaml.v3`。不带参数运行 `srpg` 会列出全部命令。

## 包

| 包 | 内容 |
|---|---|
| `rules` | 战斗状态、移动、伤害、状态效果、行动的校验和执行、回合流程、敌人 AI、洞穴机制、数据表读取（支持变体的覆盖目录） |
| `bots` | 玩家机器人（新手、熟练）和局面评估 |
| `sim` | 单场战斗、多核批量模拟、回放、静态伤害矩阵 |
| `balance` | 统计、设计目标判定、自适应停止、参数扫描、报告、数据表和静态规格检查 |
| `studio` | 战棋工坊的服务端（变体、任务、HTTP 接口、事件推送）；网页前端在 `balance/web/` |
| `play` | 给 Godot 可玩原型用的本地规则服务（`srpg play`，由游戏自己启动和关闭） |
| `splat` | 从关卡数据生成像素风格的高斯泼溅沙盘，并渲染成像素画 |
| `cmd/srpg` | 命令行；每组命令在自己的 `cmd_*.go` 里注册 |

数据表仍在 `prototype/data/tables/`；设计目标、静态规格、表结构在 `balance/targets/`、`balance/specs/`、`balance/schemas/`；模拟结果和变体在 `balance/out/`、`balance/workspace/`。

## 常用命令

在项目根目录下运行。

| 命令 | 作用 |
|---|---|
| `srpg studio` | 打开战棋工坊（http://127.0.0.1:8765） |
| `srpg check` | 数据表校验 + 引用一致性 + 静态规格，结尾打印"几下打死"表 |
| `srpg run 1-4` | 把目标文件里的每个机器人模拟到有定论，再出报告 |
| `srpg sweep 1-5 --set units:lion.str=12,14,16` | 参数扫描，逐轮淘汰 |
| `srpg report 1-4` | 只按已有结果判定并生成报告 |
| `srpg simulate -battle 1-4 -bot skilled -runs 400 -out runs.jsonl` | 只跑模拟，每场一行 JSON |
| `srpg replay -battle 1-4 -bot skilled -seed 7` | 一场战斗的逐步回放 |
| `srpg bench -battle 1-4` | 测模拟速度 |
| `srpg splat` | 生成 1-5 的沙盘（`.ply`）和预览图，输出到 `art/splatgen/out/` |

## 速度（i7-14700KF，28 线程）

| 项目 | 以前 | 现在 |
|---|---|---|
| 1-4 熟练机器人 400 场 | Godot 单进程约 616 秒（按 40 场推算） | 单线程 2.4 秒，全部线程约 0.26 秒 |

## 和旧实现的对拍

Go 的规则是从 GDScript 版逐行移植的，移植时用 Godot 4.7.2 的输出做了对拍：1-4、1-5、test 三个关卡 × 两种机器人，加上变体目录、`--set` 覆盖、不同技能选择等情况，共 1940 场，每场的结果行逐字节相同（只排除耗时字段）。为此照搬了 Godot 的随机数发生器和排序算法，见 `rules/rng.go`、`rules/sort.go`。

对拍用的参考数据在 `testdata/parity/`，`go test ./sim/...` 每次都会检查。**以后改规则，这些参考数据要跟着删除或换成 Go 自己的快照**：GDScript 版已从工程里删除（存档在 `testdata/parity/gdscript_engine.zip`），这些数据只证明"移植时两边一致"。

统计部分同样对拍过：30 组已有结果的 540 条判定和 Python 版一致，区间相差不超过 1e-9。

## 移植时照搬的已知问题

这些是 GDScript 版原有的行为，为了对拍一致而原样保留，还没有修。修之前先确认要不要，因为会改变模拟结果。

1. 机器人的威胁缓存只按"敌人、敌人位置"做键，内容却取决于第一次查询时我方的站位，所以评估顺序会影响结果。
2. 机器人会转向藏在洞里的狮子（按它最后的位置）。
3. 伤害热力图和击杀位置记的是一批事件结束后的位置（击退、移动之后），不是受击时的位置。
4. 视线从单位的左上角格子算起，不是中心，对 2×2 单位不对称。
5. 大型单位的森林掩护和回合末地形效果只看锚点格。
6. 援护（截击）不重新校验射程和视线。
7. 藏起来的 Boss 仍然会受回合末地形和状态结算的影响。
8. `control_immune` 在特定顺序下会在同一次结算里被重新给予又清除。
9. 参数扫描里，新手机器人在 1-5 上的 Logit 拟合不收敛，给出的区间没有意义。
